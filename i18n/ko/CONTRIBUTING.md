# 기여 가이드

이름 하나, 댓글 하나, 영상 타임스탬프 하나, 또는 오타 하나를 고치는 것도 환영합니다. 댓글 창의 새로운 버전도 수록합니다. 먼저 "공인된 정사"가 되어야 참여할 수 있는 것은 아닙니다.

## Git을 몰라도 참여할 수 있습니다

### 단서만 제공하기

GitHub 저장소에서 **Issues → New issue**를 열고 "설정이나 출처 추가" 또는 "정정과 버전 차이"를 선택하세요. 무엇을 보았는지, 어디서 보았는지, 누가 관련되었는지 설명하고 가능하면 원본 링크와 타임스탬프나 댓글 맥락을 첨부하세요.

원본 링크를 아직 찾지 못해도 Issue를 올릴 수 있습니다. 이때는 "확인 대기"라고 명시하세요. 메인테이너는 우선 단서로 다루며, 확인된 영상 내 설정으로 바로 쓰지 않습니다.

### 웹에서 직접 편집하기

1. 해당 인물 등 항목의 `.md` 파일을 열고 편집 버튼을 클릭합니다.
2. 쓰기 권한이 없으면 GitHub 안내에 따라 Fork하고 자신의 복사본을 편집합니다.
3. 완료 후 짧은 커밋 메시지를 작성하고 Pull Request를 엽니다.
4. PR에 무엇을 바꿨는지, 출처가 무엇인지 적고 메인테이너 리뷰를 기다립니다.

문서 편집에 Python 설치가 필요하지는 않습니다. 자동 검사 결과는 PR에 표시됩니다.

## Git으로 제출하기

먼저 GitHub에서 **Fork**를 클릭하고 자신의 Fork 클론 주소를 복사합니다. 아래 주소의 `YOUR-USERNAME`은 자신의 계정으로 바꾸고, Fork 이름을 변경했다면 저장소 이름도 함께 바꾸세요.

```bash
git clone https://github.com/YOUR-USERNAME/mj-universe-wiki.git
cd mj-universe-wiki
git switch -c docs/add-character-detail
# 해당 항목을 편집하고, 파일을 추가하면 해당 README 색인도 갱신
python3 scripts/check_docs.py
git add characters/ sources/
git commit -m "docs: 인물 관계 출처 추가"
git push -u origin docs/add-character-detail
```

그다음 자신의 Fork 페이지에서 **Contribute → Open pull request**를 선택하고 대상이 원본 저장소의 `main`인지 확인합니다.

프로젝트에 처음 기여하기 전에 GitHub의 Settings → Emails에서 자신의 `noreply` 주소를 확인해 로컬 저장소에 설정할 수 있습니다.

```bash
git config user.name "공개 이름"
git config user.email "GitHub 설정에서 복사한 noreply 주소"
```

커밋 전에 실제로 사용할 수 있는 값을 입력하세요. 예시 문구를 그대로 쓰지 마세요. 이렇게 하면 개인 이메일을 노출하지 않고 공개 이름으로 참여할 수 있습니다.

GitHub 참고: [Fork 및 PR 흐름](https://docs.github.com/en/get-started/exploring-projects-on-github/contributing-to-a-project), [커밋 이메일 설정](https://docs.github.com/en/account-and-profile/how-tos/email-preferences/setting-your-commit-email-address).

## 내용을 어디에 두는가

| 내용 | 저장 위치 | 항목을 추가할 때 |
| --- | --- | --- |
| 인물, 부모, 후손, 별칭, 신분 버전 | `characters/인물명.md` | 인물 템플릿을 복사하고 인물 색인 갱신 |
| 파트너, 사제, CP, 관계가 불분명한 이름 | `relationships/` | 관계 방향과 적용 버전을 명시하고 색인 갱신 |
| 세계 규칙과 유니버스 차이 | `universes/유니버스명/README.md` | 인물 파일을 링크하고 유니버스별로 인물을 복제하지 않음 |
| 클래식 밈, 말버릇과 사용 대상 | `memes/` | 누가 누구에게 어떤 상황에서 쓰는지 작성 |
| 유니버스 전용 스토리 패턴 | `universes/유니버스명/patterns/` | 발단, 확대, 결과를 설명하고 영상 예시를 붙여 색인 갱신 |
| 유니버스를 넘어 재사용되는 패턴 | `universes/patterns/` | 대표 유니버스, 재사용 범위, 차이를 표시하고 다른 유니버스는 링크만 |
| 원본 영상, 댓글, 탄막 관찰 기록 | `sources/` | 출처 템플릿을 복사하고 사용하지 않은 번호를 배정해 출처 색인 갱신 |

출처 번호는 기존 번호에서 이어 올리고, 오래된 번호를 다시 매기지 않습니다. 동시에 같은 새 번호를 썼다면 PR 리뷰에서 조정하세요. 인물 이름은 인물 파일 한 곳에서만 관리하고, 다른 페이지는 이를 링크해 서로 충돌하는 명단을 중복 관리하지 않습니다.

인물의 역할, 성격, 행동 습관, 말투, 유니버스별 모습도 환영합니다. 모든 요약에는 구체적인 영상 예시를 붙이고 "똑똑하다", "속이 검다" 같은 빈 라벨만 쓰지 마세요. 카메오는 어떤 인물 버전을 쓰는지 명시하며, 그 버전의 모든 관계를 자동으로 물려받지 않습니다.

템플릿: [유니버스](../../templates/宇宙模板.md) · [스토리 패턴](../../templates/故事模式模板.md) · [인물](../../templates/人物模板.md) · [출처](../../templates/来源模板.md) · [단일 설정](../../templates/设定模板.md). 기존 항목에 한 줄만 더할 때는 템플릿 전체를 복사하지 않아도 됩니다.

## 유용한 기여란

예를 들어 출처 기록 [R09](../../sources/R09.md)에는 "헐크의 아버지는 녹두탕"이라는 댓글 관찰이 저장되어 있습니다.

- 관계: 헐크 → 아버지 → 녹두탕.
- 유형: 댓글 공동 창작. 영상 내 대사로 표시하지 않음.
- 위치: 원본 영상의 공개 댓글. 답글 맥락을 설명하고, 안정적인 댓글 링크가 없으면 영상 페이지를 링크.
- 버전: 다른 아버지 이름을 남기고, 한 댓글을 유일한 명단으로 승격하지 않음.

이 예시는 기존 자료를 인용한 것이며, 새로운 기여자가 원본 페이지를 다시 확인했다는 뜻은 아닙니다. 실제 제출 시 제목, 댓글, 이미지, 클립, 전체 영상 중 무엇을 보았는지 설명하세요.

## 출처 유형과 버전 차이

| 라벨 | 의미 |
| --- | --- |
| 영상 내 설정 | 대사나 화면에서 명확히 표현됨. 가능하면 타임스탬프 제공 |
| 작가 보충 | 설명란, 고정 댓글, 작가 답글 |
| 댓글 공동 창작 | 댓글 릴레이, 탄막, 추측, 댓글 이미지 |
| 정리 추론 | 자료에 근거한 해석. 근거와 불확실성을 명시 |
| 창작 확장 | 새로운 창작 버전. 기존 작품의 사실로 쓰지 않음 |
| 확인 대기 단서 | 출처가 아직 없거나 간접 단서만 있음. 우선 Issue로 제출 가능 |

관계가 불분명하면 불분명한 채로 두고, 버전이 충돌하면 작가·브랜치·에피소드를 나란히 설명합니다. 이름이 등장했다고 해서 아버지, 어머니 등 세대 관계가 자동으로 증명되지는 않습니다. 자동 자막의 동음이의어도 불확실성을 남깁니다. 무효가 된 출처는 원본 링크와 당시 확인 범위를 남기고, 출처 없이 결론을 바꾸지 마세요.

## 리뷰와 유지 관리

하나의 PR은 한 인물, 한 출처, 한 주제에 집중하세요. 오타는 바로 고쳐도 됩니다. 메인테이너는 출처 경계, 상호 링크, 버전 차이를 중시하며, 개인 취향에 맞지 않는다는 이유만으로 버전을 삭제하지 않습니다.

일반 기여자는 자신의 Fork로 push합니다. 쓰기 권한이 있는 메인테이너는 토픽 브랜치를 직접 push하고 PR을 낼 수 있습니다. 쓰기 권한 부여와 `main` 보호는 저장소 공개 후 GitHub에서 설정해야 하며, 로컬 문서만으로 자동 적용되지 않습니다. `main`은 PR로 병합하고 `docs-check` 통과를 요구할 것을 권장합니다.
