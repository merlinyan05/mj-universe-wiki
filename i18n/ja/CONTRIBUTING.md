# 貢献ガイド

名前一つ、コメント一つ、動画のタイムスタンプ一つ、あるいは誤字一つの訂正でも歓迎です。コメント欄の新しいバージョンも収録します。「公認の正史」になってからでないと参加できない、ということはありません。

## Git が分からなくても参加できます

### 手がかりだけ提供する

GitHub リポジトリで **Issues → New issue** を開き、「設定や出典の追加」または「訂正とバージョン差」を選びます。何を見たか、どこで見たか、誰が関わるかを説明し、可能なら元リンクとタイムスタンプやコメントの文脈を添えてください。

元リンクがまだ見つからなくても Issue を提出できます。その場合は「要確認」と明記してください。メンテナーはまず手がかりとして扱い、確認済みの本編設定として書き込みません。

### Web で直接編集する

1. 該当する人物など条目の `.md` ファイルを開き、編集ボタンをクリックします。
2. 書き込み権限がない場合は、GitHub の案内に従って Fork し、自分のコピーを編集します。
3. 完了したら短いコミットメッセージを書き、Pull Request を作成します。
4. PR に何を変更したか、出典は何かを書き、メンテナーのレビューを待ちます。

文書の編集に Python のインストールは不要です。自動チェックの結果は PR に表示されます。

## Git で提出する

まず GitHub で **Fork** をクリックし、自分の Fork のクローン URL をコピーします。以下のアドレスの `YOUR-USERNAME` は自分のアカウントに置き換えてください。Fork 名を変更した場合はリポジトリ名も置き換えます。

```bash
git clone https://github.com/YOUR-USERNAME/mj-universe-wiki.git
cd mj-universe-wiki
git switch -c docs/add-character-detail
# 該当する条目を編集。ファイルを追加したら対応する README 索引も更新
python3 scripts/check_docs.py
git add characters/ sources/
git commit -m "docs: 人物関係の出典を追加"
git push -u origin docs/add-character-detail
```

その後、自分の Fork ページで **Contribute → Open pull request** を選び、宛先が元リポジトリの `main` であることを確認します。

初めてプロジェクトに貢献する前に、GitHub の Settings → Emails で自分の `noreply` アドレスを確認し、ローカルリポジトリに設定できます。

```bash
git config user.name "あなたの公開名義"
git config user.email "GitHub 設定からコピーした noreply アドレス"
```

コミット前に実際に有効な値を入力してください。例のテキストをそのまま使わないでください。これにより私人メールを公開せず、公開名義で参加できます。

GitHub 参考：[Fork と PR の流れ](https://docs.github.com/en/get-started/exploring-projects-on-github/contributing-to-a-project)、[コミットメールの設定](https://docs.github.com/en/account-and-profile/how-tos/email-preferences/setting-your-commit-email-address)。

## 内容をどこに置くか

| 内容 | 保存場所 | 条目を追加するとき |
| --- | --- | --- |
| 人物、親、子孫、別名、身分バージョン | `characters/人物名.md` | 人物テンプレートを複製し、人物索引を更新 |
| コンビ、師弟、CP、関係不明の名前 | `relationships/` | 関係の方向と適用バージョンを明記し、索引を更新 |
| 世界のルールとユニバース差 | `universes/宇宙名/README.md` | 人物ファイルをリンクし、宇宙ごとに人物を複製しない |
| 定番ネタ、口癖とその対象 | `memes/` | 誰が誰に、どんな状況で使うかを書く |
| 宇宙専用の物語パターン | `universes/宇宙名/patterns/` | きっかけ、エスカレーション、結末を説明し、本編例を添えて索引を更新 |
| 宇宙をまたいで再利用できるパターン | `universes/patterns/` | 典型宇宙、再利用範囲、差異を明記し、他の宇宙からはリンクのみ |
| 元動画、コメント、弾幕の観察記録 | `sources/` | 出典テンプレートを複製し、未使用番号を割り当てて出典索引を更新 |

出典番号は既存番号から増やし、古い番号を振り直しません。同時に同じ新番号を使った場合は PR レビューで調整してください。人物名は人物ファイルだけを唯一の管理場所とし、他のページはそれをリンクして、矛盾する名簿を二重管理しないようにします。

人物の役割、性格、行動習慣、話し方、ユニバースごとの見え方も歓迎です。各要約には具体的な本編例を添え、「賢い」「腹黒い」だけの空疎なラベルにしないでください。カメオはどの人物バージョンを使うかを明記し、そのバージョンの関係を自動的にすべて引き継がないようにします。

テンプレート：[ユニバース](../../templates/宇宙模板.md) · [物語パターン](../../templates/故事模式模板.md) · [人物](../../templates/人物模板.md) · [出典](../../templates/来源模板.md) · [単一設定](../../templates/设定模板.md)。既存条目に一行だけ足す場合は、テンプレート全体を複製する必要はありません。

## 役に立つ貢献とは

例えば出典記録 [R09](../../sources/R09.md) には「ハルクの父は緑豆湯」というコメント観察が保存されています。

- 関係：ハルク → 父 → 緑豆湯。
- 種類：コメント共創。本編の台詞としては扱わない。
- 位置：元動画の公開コメント。返信の文脈を説明し、安定したコメントリンクがない場合は動画ページをリンクする。
- バージョン：他の父の名前を残し、一つのコメントを唯一の名簿に昇格させない。

この例は既存資料を引用したもので、新しい貢献者が元ページを再確認したという意味ではありません。実際に提出する際は、タイトル、コメント、画像、クリップ、完全な動画のどれを見たかを説明してください。

## 出典の種類とバージョン差

| ラベル | 意味 |
| --- | --- |
| 本編設定 | 台詞や画面で明確に表現されている。可能ならタイムスタンプを添える |
| 作者補足 | 概要欄、固定コメント、作者の返信 |
| コメント共創 | コメントのしりとり、弾幕、推測、コメント画像 |
| 整理上の推論 | 材料に基づく解釈。根拠と不確実性を明記 |
| 独自拡張 | 新しい創作バージョン。既存作品の事実として書かない |
| 要確認の手がかり | 出典がまだない、または間接的な手がかりのみ。まず Issue で提出可 |

関係が不明なら不明のままにし、バージョンが衝突する場合は作者・ブランチ・単集を並べて説明します。名前が出ただけでは父・母などの世代を自動的に証明しません。自動字幕の同音異義語も不確実性を残します。無効になった出典は元リンクと当時の確認範囲を残し、出典なしに結論を書き換えないでください。

## レビューとメンテナンス

一つの PR は一人の人物、一つの出典、一つの話題に絞ってください。誤字は直接直して構いません。メンテナーは出典の境界、相互リンク、バージョン差を重視し、個人的な好みに合わないという理由だけでバージョンを削除しません。

一般の貢献者は自分の Fork に push します。書き込み権限を持つメンテナーはトピックブランチを直接 push して PR を出せます。書き込み権限の付与と `main` の保護はリポジトリ公開後に GitHub で設定する必要があり、ローカル文書から自動で有効になるものではありません。`main` は PR 経由でマージし、`docs-check` の通過を必須とすることを推奨します。

## ライセンスとプライバシー

オリジナルの整理を提出することは、自分が権利を有する部分を [CC BY-SA 4.0](../../LICENSE) で共有することに同意し、著作者人格権を保持することを意味します。著作権の譲渡は不要です。権利を持たない第三者コンテンツは、必要な短い引用、要約、出典のみを残し、帰属を明確にしてください。詳細は[クレジット](ATTRIBUTION.md)を参照してください。

私的なチャット、実際の家族情報、アカウント認証情報、ローカルの絶対パス、無関係な個人情報を提出しないでください。来歴のために公開クリエイター名を残すことはできますが、コメント者の連絡先やプロフィールを追加収集しないでください。他の貢献者を尊重し、資料そのものについて議論してください。
