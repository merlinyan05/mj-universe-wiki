# 貢献ガイド

名前一つ、コメント一つ、動画のタイムスタンプ一つ、あるいは誤字一つの訂正でも歓迎である。コメント欄の新しいバージョンも収録する。「公認の正史」になってからでないと参加できない、ということはない。

## Git が分からなくても参加できます

### 手がかりだけ提供する

GitHub リポジトリで **Issues → New issue** を開き、「設定や出典の追加」または「訂正とバージョン差」を選ぶ。何を見たか、どこで見たか、誰が関わるかを説明し、可能なら元リンクとタイムスタンプやコメントの文脈を添えてください。

元リンクがまだ見つからなくても Issue を提出できる。その場合は「要確認」と明記してください。メンテナーはまず手がかりとして扱い、確認済みの本編設定として書き込まない。

### Web で直接編集する

1. 該当する人物など条目の `.md` ファイルを開き、編集ボタンをクリックする。
2. 書き込み権限がない場合は、GitHub の案内に従って Fork し、自分のコピーを編集する。
3. 完了したら短いコミットメッセージを書き、Pull Request を作成する。
4. PR に何を変更したか、出典は何かを書き、メンテナーのレビューを待つ。

文書の編集に Python のインストールは不要である。自動チェックの結果は PR に表示される。

## Git で提出する

まず GitHub で **Fork** をクリックし、自分の Fork のクローン URL をコピーする。以下のアドレスの `YOUR-USERNAME` は自分のアカウントに置き換えてください。Fork 名を変更した場合はリポジトリ名も置き換える。

```bash
git clone https://github.com/YOUR-USERNAME/mj-universe-wiki.git
cd mj-universe-wiki
git switch -c docs/add-character-detail
# 該当する条目を編集。ファイルを追加したら対応する README 索引も更新
python3 scripts/check_docs.py
git add characters/ sources/
git commit -m "docs: 人物関係の出典を追加"
git push -u origin docs/add-character-detail
```

その後、自分の Fork ページで **Contribute → Open pull request** を選び、宛先が元リポジトリの `main` であることを確認する。

初めてプロジェクトに貢献する前に、GitHub の Settings → Emails で自分の `noreply` アドレスを確認し、ローカルリポジトリに設定できる。

```bash
git config user.name "あなたの公開名義"
git config user.email "GitHub 設定からコピーした noreply アドレス"
```

コミット前に実際に有効な値を入力してください。例のテキストをそのまま使わないでください。これにより私人メールを公開せず、公開名義で参加できる。

GitHub 参考：[Fork と PR の流れ](https://docs.github.com/en/get-started/exploring-projects-on-github/contributing-to-a-project)、[コミットメールの設定](https://docs.github.com/en/account-and-profile/how-tos/email-preferences/setting-your-commit-email-address)。

## 内容をどこに置くか

| 内容 | 保存場所 | 条目を追加するとき |
| --- | --- | --- |
| 人物、親、子孫、別名、身分バージョン | `characters/人物名.md` | 人物テンプレートを複製し、人物索引を更新 |
| コンビ、師弟、CP、関係不明の名前 | `relationships/` | 関係の方向と適用バージョンを明記し、索引を更新 |
| 世界のルールとユニバース差 | `universes/宇宙名/README.md` | 人物ファイルをリンクし、宇宙ごとに人物を複製しない |
| 定番ネタ、口癖とその対象 | `memes/` | 誰が誰に、どんな状況で使うかを書く |
| 宇宙専用の物語パターン | `universes/宇宙名/patterns/` | きっかけ、エスカレーション、結末を説明し、本編例を添えて索引を更新 |
| 宇宙をまたいで再利用できるパターン | `universes/patterns/` | 典型宇宙、再利用範囲、差異を明記し、他の宇宙からはリンクのみ |
| 元動画、コメント、弾幕の観察記録 | `sources/` | 出典テンプレートを複製し、未使用番号を割り当てて出典索引を更新 |
| 現実の起源、伝播の節目と初出論争 | `docs/MJ_HISTORY.md` | 先に出典記録を作り、初出・転載・再アップロード・回想を区別し、回查可能な公開日時と位置を付ける |

出典番号は既存番号から増やし、古い番号を振り直さない。同時に同じ新番号を使った場合は PR レビューで調整してください。人物名は人物ファイルだけを唯一の管理場所とし、他のページはそれをリンクして、矛盾する名簿を二重管理しないようにする。

人物の役割、性格、行動習慣、話し方、ユニバースごとの見え方も歓迎である。各要約には具体的な本編例を添え、「賢い」「腹黒い」だけの空疎なラベルにしないでください。カメオはどの人物バージョンを使うかを明記し、そのバージョンの関係を自動的にすべて引き継がないようにする。

テンプレート：[ユニバース](templates/宇宙模板.md) · [物語パターン](templates/故事模式模板.md) · [人物](templates/人物模板.md) · [出典](templates/来源模板.md) · [単一設定](templates/设定模板.md)。既存条目に一行だけ足す場合は、テンプレート全体を複製する必要はない。

## 画像とスタンプの提出方法

### 人物の三面図と外観参考

現在の入口は[人物ファイルの外観参考](characters/README.md#外観参考)を参照。該当する `characters/人物名.md` の「外観参考（外部リンク）」に、出典ページ、作者または発行者（判明している場合）、映画／ゲーム／二次創作／MJ作者版、実際の視点、確認日と範囲、および許諾が確認済みかどうかを追加する。公式または作者の原ページへのリンクを優先し、図庫の入口を使う場合は図庫の収録であることを明記し、図庫を原作者として扱わない。三面図と一般的な多角度展示は分けて書く。

許諾が未確認の場合は通常のテキストリンクのみを追加し、リポジトリへダウンロードせず、Markdown 画像構文でリモート原図を埋め込まない。自由な転載、商用利用、AI 生成利用を宣伝しない。参考リンクは許諾の証明ではなく、MJ 本編の外観や人物関係の考証証拠にもしない。将来、自作または AI 生成の参考画像を提出する場合は、コミュニティ創作版であること、制作方法、第三者キャラクターの権利境界を明記し、下記の配図ルールで審査する。

### まず画像が何の理解を助けるかを説明する

本リポジトリは MJ ユニバースの設定を整理し、画像は人物、関係、世界線、定番ネタの理解または Wiki 展示に資する。提出時には答えてもらいたい：**この画像は読者がどの設定を理解する助けになるか、またはどのような明確な展示用途を持つか？**

| 項目とともに収録できるもの | 用途の説明方法 |
| --- | --- |
| README 表紙、人物識別図、関係図、世界線示意図 | 展示位置または関連項目を明示する。自作・AI 生成の示意図は本編証拠と分けて注記する |
| 具体的な設定や定番ネタを裏付けるスクリーンショット | 対応項目をリンクし、原リンク、時点またはコメント文脈、作者版、実際の確認範囲を記録する |
| 動作でしか理解できない短い GIF | 静止画では表せない動作を説明し、その項目に必要な片段のみを残す |

汎用のマーベル絵文字、壁紙、ちびキャラステッカーその他の一般素材集は、文字索引と外部リンクで紹介する。転載許諾があっても、上記の内容範囲に合致する必要がある。「後で動画に使えるかも」だけでは設定との関係を説明したことにならない。

### 一般素材集は索引と外部リンクを使う

`memes/` に素材索引を追加し、外部の保管場所や独立した素材リポジトリへリンクできる。画像一式を先に本リポジトリへコミットする必要はない。索引には、合集名、対象キャラクターやテーマ、設定集との関係、アクセスリンク、出典と権利状態、数量と内容を実際にどこまで確認したかを書く。整理者だけが提供する数字は「整理者提供、未だ項目別未確認」と明記する。

外部リンクは本リポジトリが全画像を審査済みであることや、素材の使用権を与えることを意味しない。索引でも、設定の検索や関連創作に具体的にどう役立つかを説明し、無関係なリンクを積み上げない。

### 項目への配図の提出方法

ネタ画像は `memes/images/キャラクター名/` に置ける。例：`memes/images/灭霸/emo_reply.jpg`。表紙や Wiki 展示画像は `assets/images/` に置ける。対応する項目で相対パスで表示する。例：

```markdown
![傷感コピーがあだ名にされたコメントのスクリーンショット](images/灭霸/emo_reply.jpg)
```

例のパスはすでに収録済みという意味ではない。実際に提出する画像に置き換える。収録する各画像は項目または一覧から辿れるようにし、関連項目または展示用途、原リンクまたは生成説明、制作者（判明時）、適用版、実際の確認範囲、転載許諾または権利根拠を記録する。素材索引を追加するときは `memes/README.md` に索引を追加する。

[第三者資料の説明](ATTRIBUTION.md)に従い、収録範囲に合うオリジナルまたは明確な転載許諾のある画像は PR で提出できる。転載許諾が未確認のネット画像は、まず出典リンクと文字索引を収録する。出典リンク、第三者著作権表示、転載許諾は別々に説明し、第三者素材を本リポジトリの CC ライセンスに自動的に切り替えない。提出前に画像内の個人情報も確認する。

### ファイル形式と確認

JPG／JPEG、PNG、GIF、WebP に対応する。拡張子は実際の形式と一致させる。アニメーションや透明チャンネルが必要なときは元素材を確認する。静止 JPEG の拡張子を変えたり形式変換したりしても、アニメーションや透明チャンネルは復元されない。

画像だけのディレクトリは階層ごとに README を作る必要はない。Markdown 資料を含むディレクトリには README 索引が必要。画像リンクはファイルの存在を確認する。検査スクリプトは上記画像形式をバイナリで読み、ファイルヘッダーを確認する。**スクリプト通過は技術的検査に合格しただけで、収録用途、出典、版、権利状態は人手で審査する必要がある。**

第三者の Python パッケージをインストールせずに、ローカルで次を実行できる。

```bash
python3 scripts/check_docs.py
python3 -m unittest discover -s tests -v
```

## 役に立つ貢献とは

例えば出典記録 [R09](sources/R09.md) には「ハルクの父は緑豆湯」というコメント観察が保存されている。

- 関係：ハルク → 父 → 緑豆湯。
- 種類：コメント共創。本編の台詞としては扱わない。
- 位置：元動画の公開コメント。返信の文脈を説明し、安定したコメントリンクがない場合は動画ページをリンクする。
- バージョン：他の父の名前を残し、一つのコメントを唯一の名簿に昇格させない。

この例は既存資料を引用したもので、新しい貢献者が元ページを再確認したという意味ではない。実際に提出する際は、タイトル、コメント、画像、クリップ、完全な動画のどれを見たかを説明してください。

## 出典の種類とバージョン差

| ラベル | 意味 |
| --- | --- |
| 本編設定 | 台詞や画面で明確に表現されている。可能ならタイムスタンプを添える |
| 作者補足 | 概要欄、固定コメント、作者の返信 |
| コメント共創 | コメントのしりとり、弾幕、推測、コメント画像 |
| 整理上の推論 | 材料に基づく解釈。根拠と不確実性を明記 |
| 独自拡張 | 新しい創作バージョン。既存作品の事実として書かない |
| 要確認の手がかり | 出典がまだない、または間接的な手がかりのみ。まず Issue で提出可 |

関係が不明なら不明のままにし、バージョンが衝突する場合は作者・ブランチ・単集を並べて説明する。名前が出ただけでは父・母などの世代を自動的に証明しない。自動字幕の同音異義語も不確実性を残す。無効になった出典は元リンクと当時の確認範囲を残し、出典なしに結論を書き換えないでください。

## レビューとメンテナンス

一つの PR は一人の人物、一つの出典、一つの話題に絞ってください。誤字は直接直して構わない。メンテナーは出典の境界、相互リンク、バージョン差を重視し、個人的な好みに合わないという理由だけでバージョンを削除しない。

一般の貢献者は自分の Fork に push する。書き込み権限を持つメンテナーはトピックブランチを直接 push して PR を出せる。書き込み権限の付与と `main` の保護はリポジトリ公開後に GitHub で設定する必要があり、ローカル文書から自動で有効になるものではない。`main` は PR 経由でマージし、`docs-check` の通過を必須とすることを推奨する。

## ライセンスとプライバシー

オリジナルの整理を提出することは、自分が権利を有する部分を [CC BY-SA 4.0](../../LICENSE) で共有することに同意し、著作者人格権を保持することを意味する。著作権の譲渡は不要である。権利を持たない第三者コンテンツは、必要な短い引用、要約、出典のみを残し、帰属を明確にしてください。詳細は[クレジット](ATTRIBUTION.md)を参照してください。

私的なチャット、実際の家族情報、アカウント認証情報、ローカルの絶対パス、無関係な個人情報を提出しないでください。来歴のために公開クリエイター名を残すことはできますが、コメント者の連絡先やプロフィールを追加収集しないでください。他の貢献者を尊重し、資料そのものについて議論してください。

## 同名親族の異なる版を記録する

父母表に衝突が現れたときは、「作者／具体作品＋親族方向＋原字形＋位置」を補うことを優先し、一つの名前ですべてを上書きしない。例えば同じ字面の名前がある作品では兄、別の作品では祖父である場合、両方を残す。歌、アップロード者の配図、本編自述、コメントしりとりも種類別に記録する。

新しい証拠で以前の要確認関係が確認できたときは、人物ファイルに新出典を補い、旧候補ページに補証済みと注記する。旧出典が当時タイトル／コメントだけを読んだ範囲は残す。必要に応じて人物索引、関係ページ、ユニバース入口を同期し、一ページが確認済みなのに別ページがすべて未確認と書く状態を避ける。

単話の臨時職務、騙し言葉の中の権威呼称、証明書を借りた身分は、そのまま永久の人物属性に格上げできない。クロスユニバース客演は来客と現地人の区別を明記する。具体例は[客演の説明](universes/跨宇宙与客串.md)を参照。
